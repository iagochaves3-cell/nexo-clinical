## Incremento

1. `POST /v1/evidence/search`: busca real Europe PMC, restrita a registros PubMed;
   PMID, DOI quando fornecido, data, tipo de publicação, URL, consulta executada,
   data de recuperação e hash do título/resumo. Resultado não confirma aplicabilidade.
2. `POST /v1/clinical/review`: busca antes da revisão, contexto pediátrico restrito,
   afirmações identificadas e rascunho por provedor OpenAI opcional. Aceita somente
   IDs recuperados e citações literais contidas nos resumos; máximo 25 palavras
   por fonte. Respostas com referências inventadas, cobertura incompleta ou schema
   inválido são descartadas. O rascunho nunca autoriza prescrição.
3. Sem provedor configurado: `review_unavailable`; sem resumos: `insufficient_evidence`;
   pesquisa indisponível/malformada: HTTP 503. Não simula revisão bem-sucedida.
4. Token opcional independente `NEXO_INTEGRATION_TOKEN`, restrito aos novos endpoints
   e capabilities; o token administrativo original continua aceito e não foi alterado.
5. Adaptadores por domínio: `fluid_therapy`, `mechanical_ventilation`, `prescription`.
   Os cálculos e as recomendações locais não foram substituídos.
6. Preparação específica PPS em `integrations/pps/`; não publicada nem ligada à interface.

restrição, imprimir segredo, substituir token ou coletá-lo pelo chat.

Após liberar escrita do conector GitHub e publicar a branch revisada:

- Railway NEXO: manter `NEXO_API_TOKEN`; adicionar `NEXO_INTEGRATION_TOKEN` aleatório

  e structured outputs. Nenhum modelo pago foi presumido/configurado nesta entrega.
- Serviços satélites: `SERVICE_API_TOKEN` próprio, `NEXO_API_URL` igual à URL publicada,

  variáveis públicas de frontend nem colocar chaves no repositório.

Nenhuma credencial nova foi configurada em produção: o código remoto ainda não
